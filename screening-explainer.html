What is Address Screening?

Address Screening is the simplest Chainalysis API, one endpoint, one call. Pass in any blockchain address and get back a complete risk assessment: risk level, entity identifications, on-chain exposure breakdown, and any compliance rules that triggered. Use it to gate wallet connections, onboarding, deposits, or any point where a new address enters your platform.

New address appears → One API call → Full risk assessment → Allow / Review / Block
1

Screen an Address

One GET request with the address. That's the entire integration. Chainalysis identifies the address across all supported blockchains, checks it against sanctions lists, known entities, and on-chain risk data, and returns a comprehensive risk assessment.

Where this fits: Call this at wallet connection, account onboarding, before accepting a deposit, or any time a new address enters your system. It's fast enough to run inline without the user noticing any delay.

// Screen any blockchain address, one call, full assessment GET /api/risk/v2/entities/{address} // Example GET /api/risk/v2/entities/0x098B716B8Aaf21512996dC57EB0615e2383E2f96 // Headers Token: your-api-key Accept: application/json

2

Understanding the Response

The response has five key sections. Each tells you something different about the address. Here's what each field means and why it matters.

Risk Level, The top-line verdict

Low

Minimal risk detected

Medium

Some risk factors present

High

Significant risk indicators

Severe

Known malicious activity

FieldWhat it tells youExample
risk The overall risk verdict: Low, Medium, High, or Severe "Severe"
riskReason Human-readable explanation of why this risk level was assigned "Directly associated with a sanctioned entity"
addressType Whether it's a normal wallet or a DeFi liquidity pool "PRIVATE_WALLET" or "LIQUIDITY_POOL"
cluster If Chainalysis has identified who controls this address, the entity name and category { "name": "Binance.com", "category": "exchange" }
addressIdentifications Specific identifications: sanctions list matches, known entity names, OSINT data [{ "category": "sanctions", "name": "Lazarus Group" }]
exposures USD breakdown of on-chain exposure by risk category, with direct vs indirect tagging [{ "category": "mixer", "value": 84200000, "exposureType": "indirect" }]
triggers Which compliance rules fired and at what threshold, drives the risk level [{ "category": "sanctioned entity", "percentage": 100 }]

Direct vs Indirect exposure: Direct means the counterparty itself IS a risky entity (e.g., funds came directly from a sanctioned wallet). Indirect means funds passed through a risky entity upstream, one or more hops away. Both matter for compliance, but direct exposure is more severe.

3

Make a Decision

Based on the risk level and your compliance policy, your platform takes action. Here's a typical decision matrix, your compliance team configures the exact thresholds.

Low → Allow

Proceed normally. No compliance action required.

Medium → Review

Flag for enhanced due diligence. May require additional KYC.

High → Restrict

Block the action. Escalate to compliance team for manual review.

Severe → Block

Deny immediately. Known sanctioned or malicious entity. File SAR if required.

// Example decision logic in your platform const result = await screenAddress(walletAddress); switch (result.risk) { case "Low": allowConnection(); // ✓ Proceed normally break; case "Medium": allowWithReview(result); // ⚠ Flag for enhanced due diligence notifyCompliance(result); break; case "High": case "Severe": blockConnection(result); // ✗ Deny access alertCompliance(result); if (result.risk === "Severe") fileSAR(result); break; }
