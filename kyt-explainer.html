KYT — Know Your Transaction

API Integration Walkthrough

Chainalysis

What is KYT?

Know Your Transaction (KYT) is Chainalysis's real-time transaction monitoring API. It lets crypto businesses screen every deposit, withdrawal, and transfer for compliance risk — automatically. When funds touch sanctioned entities, darknet markets, ransomware, or other high-risk categories, KYT generates an alert so your compliance team can act before it's too late.

Customer Action → Your Platform → KYT API → ✓ Clear / ⚠ Alert
1

Create a User

Every customer on your platform gets a unique KYT user ID. This is how Chainalysis ties transactions back to a specific person — enabling per-user risk scoring, alert routing, and compliance history.

What this means for the customer: This happens behind the scenes during account creation. The customer never sees it — it's your platform registering them with Chainalysis for monitoring.

// Create a user when they sign up on your platform POST /api/kyt/v2/users { "userId": "customer-jane-doe-123" }
// Response { "userId": "customer-jane-doe-123", "createdAt": "2026-06-16T10:30:00Z" }
2

Register a Transaction

Every crypto transaction on your platform gets registered with KYT. The API endpoint and workflow differ depending on the direction — select one to see the full integration flow.

How it works: When a customer deposits crypto, your platform registers the on-chain transaction with KYT as a received transfer. KYT then monitors the transaction in real-time, tracing where the funds came from and flagging any high-risk exposure.

Customer deposits crypto → Your platform detects tx → Register with KYT → KYT monitors
// Register a deposit (received transfer) POST /api/kyt/v2/users/customer-jane-doe-123/transfers { "network": "Ethereum", "asset": "ETH", "direction": "received", "transferReference": "0xabc123...def456:0x742d35Cc..." }
// Response — KYT begins monitoring immediately { "externalId": "transfer-ext-789", "asset": "ETH", "updatedAt": null // null = still processing }

Two-step process: Withdrawals involve an additional endpoint. First, use withdrawal-attempts to pre-screen the destination address before broadcasting the transaction — blocking sanctioned wallets, darknet markets, or ransomware addresses. Then, once the withdrawal is approved and executed on-chain, register it as a sent transfer via the standard transfers endpoint for ongoing monitoring.

Customer requests withdrawal → Pre-screen destination → ✓ Allow → Register sent transfer → KYT monitors
→ ✗ Block → notify compliance

Key distinction: This is NOT the same as screening an address at onboarding. Withdrawal pre-screening happens at the moment of the transaction, catching addresses that may have been clean at onboarding but have since been sanctioned.

// ─── STEP A: Pre-screen the destination address BEFORE sending ─── POST /api/kyt/v2/users/customer-jane-doe-123/withdrawal-attempts { "network": "Bitcoin", "asset": "BTC", "address": "bc1qxy2kgdygjrsqtzq2n0yrf...", "attemptIdentifier": "withdrawal-w-001" }
// Response { "externalId": "wa-ext-456", "asset": "BTC", "attemptIdentifier": "withdrawal-w-001", "address": "bc1qxy2kgdygjrsqtzq2n0yrf...", "updatedAt": "2026-06-16T10:31:00Z" } // Check exposure on the destination address GET /api/kyt/v2/withdrawal-attempts/wa-ext-456/exposures // Response { "exposures": [ { "category": "exchange", "exposure": 0.71, "exposureType": "direct" }, { "category": "sanctioned entity", "exposure": 0.05, "exposureType": "indirect" }, { "category": "darknet marketplace", "exposure": 0.03, "exposureType": "indirect" } ] } // Check fraud risk assessment GET /api/kyt/v2/withdrawal-attempts/wa-ext-456/fraud-assessment // Response { "riskScore": 72, "riskLevel": "HIGH" } // If risk is acceptable → approve and broadcast the transaction // If risk is too high → block the withdrawal, notify compliance
// ─── STEP B: After approval, register the on-chain tx for monitoring ─── POST /api/kyt/v2/users/customer-jane-doe-123/transfers { "network": "Bitcoin", "asset": "BTC", "direction": "sent", "transferReference": "txhash:bc1qxy2kgdygjrsqtzq2n0yrf..." }
// Response { "externalId": "transfer-ext-790", "asset": "BTC", "updatedAt": null // KYT begins monitoring the sent transfer }
3

KYT Monitors & Scores

Behind the scenes, KYT traces the transaction through the blockchain. It identifies the counterparties, calculates exposure to risk categories, and assigns a risk score. This happens automatically — you just poll until the result is ready.

What KYT analyzes:

Counterparties

Who sent/received the funds?

Exposure

What % links to risky categories?

Entity Attribution

Is it a known service, mixer, or sanctioned entity?

// Poll until updatedAt is non-null GET /api/kyt/v2/transfers/transfer-ext-789
// Response (complete) { "externalId": "transfer-ext-789", "asset": "ETH", "usdAmount": 2847.32, "updatedAt": "2026-06-16T10:30:05Z" // ✓ Ready! }
4

Check Exposure

Pull the exposure breakdown to see exactly which categories of entities the funds have been associated with. Each category shows a USD value and whether the exposure is direct (the counterparty itself) or indirect (one or more hops away).

Direct Exposure

The immediate counterparty IS a risky entity

Indirect Exposure

Funds passed through a risky entity upstream

GET /api/kyt/v2/transfers/transfer-ext-789/exposures
// Response { "exposures": [ { "category": "exchange", "exposure": 0.82, "exposureType": "direct" }, { "category": "defi", "exposure": 0.12, "exposureType": "direct" }, { "category": "mixer", "exposure": 0.04, "exposureType": "indirect" }, { "category": "sanctioned", "exposure": 0.02, "exposureType": "indirect" } ] }
5

Alerts

If the exposure exceeds your configured risk thresholds, KYT automatically generates an alert. Alerts have severity levels (HIGH or SEVERE) and link to the specific risk category that triggered them. Your compliance team gets notified and can investigate.

HIGH Sanctioned Entity Exposure 2.1%

Transfer has 2.1% indirect exposure to a sanctioned entity via an intermediary mixer service.

What this means for the customer: Their deposit may be held for review. They might see a "pending compliance review" status. This protects your platform from processing illicit funds.

GET /api/kyt/v2/transfers/transfer-ext-789/alerts
// Response { "alerts": [ { "alertId": "alert-abc-456", "level": "HIGH", "categoryId": 3, "category": "sanctioned entity", "exposure": 0.021 } ] }
6

Review & Resolve

When alerts are generated, your compliance team reviews them. They can investigate the transaction in Reactor to trace fund flows visually, then make a disposition decision — clear, escalate, or file a SAR.

✓ Clear

False positive — release funds

↑ Escalate

Needs senior review or legal

📋 File SAR

Suspicious Activity Report

// Update alert status after review PATCH /api/kyt/v1/alerts/alert-abc-456 { "status": "RESOLVED" }
// Response { "alertIdentifier": "alert-abc-456", "status": "RESOLVED", "updatedAt": "2026-06-16T14:22:00Z" }
// Or assign to a specific analyst for review PATCH /api/kyt/v1/alerts/alert-abc-456/assignment { "assigneeId": "analyst@company.com" } // Response { "alertIdentifier": "alert-abc-456", "assigneeId": "analyst@company.com", "updatedAt": "2026-06-16T14:22:05Z" }
